# 设计草案：预标三桶 → 人工复审 → 数据集落版

> 状态：**已确认（D2，2026-09-09）**；按第 9 节结论落地合同/迁移/stub/fixture/测试。
> 目标：把「大图包上传 → 少量标注 → 初始训练 → 预标签 → 三桶复审 → 数据集落版 → 后续训练」的端到端数据流向与结构讲清楚，作为下一步契约 §3.4/§4.4/§10 回写与 D4/D12~D13 实现的依据。
> 归属：B（平台 A 后端 + 平台 A 前端，D2 确认）；`pipeline-core` 语义与 C 对齐。

## 0. 术语澄清（先对齐，避免歧义）

| 用户说法 | 本文用词 | 含义 |
|---|---|---|
| 模型预训练 | **初始训练 / 首轮训练** | 用当前少量已标注图片训练出一个可用模型；不是从零预训练大模型 |
| 预标签 | **预标注（prelabel）** | 用首轮模型对剩余未标注图片推理，写回 LS predictions + 三桶判定 |
| 人工 review | **人工复审** | aoi 自研复审队列；低/中桶进入人工，高桶系统自动通过 |
| 数据集落成 | **数据集版本发布（published）** | 全部复审项 finalized 后，标注（人工 + 自动通过）成为训练数据 |

> **已确认（D2）**：“模型预训练”就是“首轮训练”（在少量已标注数据上训练出首个可用模型），不是外部预训练权重导入。

## 1. 端到端数据流（按你的描述展开）

```
[0] 大图包（文件夹/压缩包）上传
        │  aoi 导入包裹（D4）：去重(md5)/坏图质检/元数据登记
        ▼
[1] LS 原生 Project + Tasks（待标注图片池）
        │  label_config = 缺陷字典渲染（RectangleLabels，code=object_fault_type_XX）
        ▼
[2] 用户选择标注形式（MVP：矩形框；多边形等见 §9 待确认）
        │  label_config 已由字典生成并注入；前端标注编辑器按 XML 渲染
        ▼
[3] 用户对少量图片人工标注（LS Annotation）
        │  aoi 记录 dataset_version（draft）+ 划分/类别统计
        ▼
[4] 用户发起“初始训练”：选择模型/基模 + 训练参数模板
        │  POST /api/train/jobs(dataset_version, framework=yolo, preset)
        ▼
[5] A 侧训练包裹（YOLO/Ultralytics）训练与 ONNX 导出（D9–D12）→ aoi_training.model(candidate)
        │  门禁/审批/ONNX 导出 → lifecycle=approved（可发布候选）
        ▼
[6] 用户选择模型发起“预标签”：POST /api/prelabel/tasks
        │  prelabel_task(model_ref, 剩余图片 scope, route_config=三桶阈值)
        ▼
[7] A 侧 worker 对剩余图片推理（pipeline-core.run + OnnxRuntimeModel）
        │  写 LS predictions（model_version/score/boxes）
        │  pipeline-core.decide_verdict → verdict/reasons → 三桶
        ▼
[8] 整个数据集进入 review 状态
        │  高（auto_pass/绿）→ 系统接受，无需人工
        │  中（recheck/黄）→ review_workitem，建议人工确认/微调
        │  低（manual/红）→ review_workitem，强制人工重标
        ▼
[9] 人工复审结束（全部 workitem finalized）
        │  final_fact + 复审后的 LS Annotation
        ▼
[10] dataset_version → published（落版）
        │  后续训练直接使用该版本（人工标注 + 自动/人工确认的预标结果）
        ▼
[11] 下一轮训练/迭代
```

## 2. 数据流与现有表的映射

| 环节 | 现有表/对象 | 说明 |
|---|---|---|
| 上传图片 | `aoi_datasets.image` + LS Project/Task | aoi 登记去重/质检/元数据；LS 原生存原图 |
| 字典/label config | `aoi_datasets.defect_class`/`defect_dict_version` + LS `Project.label_config` | 字典发布生成 XML + snapshot |
| 少量标注 | LS `Annotation`（零改动） | 用户标注仍是 LS 原生 |
| 初始训练 | `aoi_training.train_job` + `preset`/`base_model` | D9–D12 真实训练 |
| 模型注册 | `aoi_training.model` | lifecycle/gate_status/config_snapshot |
| 预标任务 | `aoi_datasets.prelabel_task` | `dataset_id`/`model_ref`/`route_config`/`route_bucket`/`status` |
| 预标结果 | LS `Prediction`（原生） + `pipeline-core.DetectResult` | `model_version`/`score`/结果；A 侧可缓存三桶结论 |
| 复审队列 | `aoi_review.review_workitem` | **当前表结构只支持 B 回传 fact，需扩展**（见 §4） |
| 终裁 | `aoi_review.final_fact` | 复审结论 + 最终 boxes/verdict |
| 回流建议 | `aoi_review.feedback_suggestion` | R1~R4 |
| 数据集版本 | `aoi_datasets.dataset_version` + `dataset_item` | 版本状态与 train/val/test 子集 |

## 3. 三桶定义与阈值来源

`pipeline-core.decide_verdict(boxes, cfg)` 已定义三档 verdict：

| 桶 | `verdict` | UI 颜色 | 语义 | 复审动作 |
|---|---|---|---|---|
| 高 | `auto_pass` | 绿 | 置信度足够，无需人工 | 系统自动接受（转 annotation / 标记通过） |
| 中 | `recheck` | 黄 | 建议人工确认 | 进队列；可一键接受/微调；不强制 |
| 低 | `manual` | 红 | 强制人工重标 | 进队列；**必须打开编辑器修改/确认**后才能 finalize |

阈值来源：

1. `model.yaml` 的 `classes[].recommended.{recheck_min,auto_min}` + `thresholds.default`；
2. `prelabel_task.route_config` 可覆盖（训练 preset 或人工微调）；
3. `pipeline-core` 还支持 `high_risk_force_recheck` / `low_score_force_manual` 全局规则。

> 建议 API/DB 同时保留 `verdict`（语义权威）与 `bucket`（UI 三桶/颜色派生），避免前端硬编码映射。

## 4. 建议的数据结构（草案，待确认）

### 4.1 现状问题

`aoi_review.review_workitem` 当前字段：

```
fact_id BIGINT NOT NULL  -- 指向 inspection_fact（B 回传）
route VARCHAR(16)        -- vlm/manual
...
```

它只表达「B 回传 suspicious」这一种来源；预标三桶的复审项**没有对应的来源表**，必须扩展，否则无法把预标结果挂到队列里。

### 4.2 方案 A（已确认采用）：泛化 `review_workitem`

新增/调整（`aoi_review` migration 0002）：

| 字段 | 类型 | 说明 |
|---|---|---|
| `fact_id` | BIGINT **NULL** | 仅 `source=ingest` 时指向 `inspection_fact` |
| `source` | VARCHAR(16) NOT NULL default `'ingest'` | `ingest` / `prelabel` |
| `dataset_version_id` | INT NULL | 预标来源：所属数据集版本 |
| `image_id` | INT NULL | 预标来源：aoi 图片 id（可选） |
| `prediction_id` | BIGINT NULL | LS `Prediction.id`（预标结果引用） |
| `model_ref` | VARCHAR(64) NULL | 产生该预标的模型 |
| `bucket` | VARCHAR(8) NULL | `high`/`medium`/`low`（UI 三桶） |
| `verdict` | VARCHAR(16) NULL | `auto_pass`/`recheck`/`manual`（pipeline-core 原始值） |
| `bucket_reason` | JSONB NULL | `{reasons:[], scores:{}, thresholds:{}}` |
| `forced` | BOOLEAN default false | 低桶强制人工 |

- 唯一性/索引建议：`(dataset_version_id, bucket, status)`、`(source, status)`；预标幂等键可与 `prediction_id`/`(dataset_version_id, task_id)` 关联。
- 高风险：`fact_id` 由 NOT NULL 改为 NULL 是**表结构变更**，需迁移；契约 §3.4 要同步。

### 4.3 方案 B（未采用）：新增 `prelabel_review_item` 表

与 `review_workitem` 平行，队列/认领/终裁逻辑要写两套，前端也要分两个接口；仅当预标复审与 B 回传复审在产品上完全独立时才考虑。

### 4.4 终裁 `final_fact` 扩展（已确认）

增加（或以 JSON 存）：

- `workitem_id`、`source`、`dataset_version_id`、`image_id`
- `annotation_id`（转成 LS Annotation 后的 id；自动通过/人工修改后写回）
- `action`：`accepted_prediction` / `edited` / `relabeled` / `no_defect` / `unlabelable`

## 5. 复审动作语义（已确认）

| 桶 | 进入队列 | 用户操作 | 数据集落版时 |
|---|---|---|---|
| 高/绿 | 可选（建议也落一条 auto-finalized 记录便于统计） | 无 | 预标结果**自动转 annotation** |
| 中/黄 | 是 | 查看预测叠加；接受、微调、驳回 | 确认后转 annotation；驳回则删除/忽略该预测 |
| 低/红 | 是（`forced=true`） | **必须打开编辑器**；重画/补框/改类/标无缺陷 | 以人工 annotation 为准；预标仅作参考 |

复审结束条件：该 `dataset_version` 下所有 `review_workitem.status=finalized`（含自动通过的记录），数据集版本才 `published`。

## 6. API 草案（D4/D12~D13 细化；D2 先落 stub/fixture）

- `GET /api/review/workitems?datasetId=&version=&bucket=&status=` → `{total,items}`；item 含 `bucket`/`bucket_color`/`forced`/`model_ref`/`image_url`/`prediction`。
- `POST /api/review/workitems/{id}/claim`（复用现有）
- `POST /api/review/workitems/{id}/finalize`：在现有 `{verdict, boxes?, final_reason, note}` 基础上增加：
  - `action`（接受预测/修改/重标/无缺陷/不可标注）
  - `annotation`（人工修改后的 LS 标注 result，可选；低桶必填）
- `POST /api/prelabel/tasks`：增加 `scope`（`unlabeled_only` 默认 / `all`）、`route_config` 覆盖。
- `GET /api/datasets/{id}/versions/{v}`：返回 `review_summary: {high,medium,low,finalized,total}` 与 `status`。

## 7. 前端体现（B 负责）

- LS 原生 Create Project 页的「Labeling Setup」预设模板仍可作为参考/自定义入口；AOI 正式流程由 aoi 数据集/训练/复审页面驱动。
- `Project.label_config` 是唯一渲染依据：前端标注编辑器读 XML 渲染 `RectangleLabels`，`from_name=defect` 与 ML backend 预测绑定。
- aoi Review 页面（`web/.../pages/Review/`）：
  - 列表按 `dataset_version` + `bucket` 分组；红/黄/绿配色；
  - 低桶卡片点开强制进入 LS 编辑器；中桶可快速接受；高桶折叠或只读统计；
  - 顶部显示 `review_summary` 进度；全部 finalize 后才允许「数据集落版/下一轮训练」。
- LS OSS 无 Review 流程，因此复审页面完全由 aoi 自研（D2 已裁定）。

## 8. 状态机（已确认）

**保留 `dataset_version.status` 原枚举（draft/published/archived），新增 `phase` 字段承载过程状态**：

```
dataset_version.phase:
  draft → labeling → training → prelabeling → reviewing → published
                                                   ↘ archived（人工废弃）
```

`prelabel_task.status`：`queued → running → succeeded/failed/canceled`（现有契约字段不变）。

`review_workitem.status`：`pending → processing → finalized/failed`（现有契约字段不变）。

## 9. 已确认结论（D2，2026-09-09）

| # | 事项 | 结论 | 落地 |
|---|---|---|---|
| 1 | 多边形/其他标注形式 | **MVP 先矩形（RectangleLabels）**；多边形/分割放 D9+ | 契约 §2.1 保持 `ObjectDetection→RectangleLabels`；skillname 预留 |
| 2 | “模型预训练”术语 | **= 首轮训练**（少量已标注数据训练首个可用模型） | 设计/契约 §10 用「首轮训练/初始训练」，不再用“预训练” |
| 3 | 三桶命名 | API **同时暴露** `verdict`（auto_pass/recheck/manual）与 `bucket`（high/medium/low） | 契约 §3.4/§4.4 + fixture |
| 4 | 高桶动作 | **高桶（auto_pass/绿）自动转 annotation**，写 auto-finalized 复审记录 | 契约 §10 + `final_fact.action=accepted_prediction` |
| 5 | `review_workitem` 扩展 | **方案 A**：`fact_id` 可空 + `source/dataset_version_id/image_id/ls_task_id/ls_prediction_id/model_ref/bucket/verdict/bucket_reason/forced` | `aoi_review` 0002 迁移 + 契约 §3.4 |
| 6 | `dataset_version` 状态 | **保留 `status`，新增 `phase`**（draft/labeling/training/prelabeling/reviewing/published/archived） | `aoi_datasets` 0002 迁移 + 契约 §3.2 |
| 7 | 预标范围 | **只对未标注图片推理**（MVP 固定 `unlabeled_only`） | 契约 §4.3；`prelabel_task` API 返回/校验 `scope=unlabeled_only` |
| 8 | 阈值优先级 | **model.yaml recommended → prelabel_task.route_config 覆盖** | `pipeline-core` + model.yaml；契约 §4.3 |
| 9 | 落版触发 | **人工确认 + 系统校验**（全部 workitem finalized、低桶已重标、校验通过后 published） | 契约 §4.4/§10；D4 实现 |
