# AOI 双平台文档索引

> 本文档集描述 **AOI 门板检测平台** 的双平台形态：训练/标注侧基于 Label Studio 二开（平台 A），
> 推理/检测侧拆分为独立轻量平台（平台 B）。两平台跨机器部署，只共享 `skillname` 与 `pipeline-core` 两个纯 Python 包。
> 最近一次结构性调整：**2026-09-09 双平台拆分**（原「LS 二开 + sidecar」单平台方案作废）。

## 2. 一句话架构

```
┌──────────────────────────── 平台 A（LS 二开，中心侧）────────────────────────────┐
│ 账户(LS)+自研RBAC · 数据集与字典 · 打标签 · 预标签 · 训练 · 模型注册/审批/发布      │
│ 人工复审/重标注 · 错图接收与回流 · 审计（不管工位/相机/实例）                        │
│ Django + DRF(LS 1.x) · PostgreSQL · MinIO · Redis + Celery · LS web(React)        │
└───────────────┬──────────────────────────────────────────────▲───────────────────┘
                │ ① 发布模型镜像（A→registry，含 model.yaml）      │ ③ 错图回传（B→A）
                ▼                                              │
┌────────────────────── 镜像仓库（Docker Hub / 内网 registry）──────────────────────┐
│ <org>/aoi-model:<tag> = /model/{model.onnx, model.yaml, model.onnx.sha256}        │
└───────────────────────────────▲──────────────────────────────────────────────────┘
                                │ ② 拉取（Registry v2 API）
┌──────────────────────────── 平台 B（独立轻量，产线侧）──────────────────────────┐
│ 拉取模型 · 自管工位/相机/工位模板(GUI) · 按模板切片推理 · 三档判定 · 检测记录      │
│ 错图统计 · 信息统计 · 日报 · 错图回传 · 回传重试(outbox)                          │
│ FastAPI + Uvicorn · SQLite · 本地磁盘 · APScheduler · ONNX Runtime · 独立 React 前端│
│ 无 RBAC/无用户认证/无登录 · 无 Redis/Celery/MinIO 依赖                              │
└──────────────────────────────────────────────────────────────────────────────────┘
                唯一共享层：packages/skillname（词汇表） + packages/pipeline-core（推理内核）
```

- ① A 发布镜像到 registry；② B 主动拉取；③ B 把可疑图/坏图回传给 A。**A 从不主动连接 B**（无实例管理、无心跳、无方案下发）。
- 平台 B 断网可用：用本地已拉取的模型继续推理，回传积压在本地 outbox，恢复后自动补传。

## 4. 术语速查

| 术语 | 含义 |
|---|---|
| 平台 A / `aoi-train` | 训练与标注平台，LS 1.x 二开，中心侧部署；账户复用 LS、**RBAC 自研** |
| 平台 B / `aoi-infer` | 推理与检测平台，独立前后端，产线侧部署，**无 RBAC / 无用户认证** |
| `skillname` | 公共包：跨平台任务类型与标签词汇（`ObjectDetection`、`object_fault_type_XX`、`model_ref` 规范） |
| `pipeline-core` | 公共包：切片/NMS 合并/类别映射/三档判定/检测配置解析（`load_config`），推理后端由调用方注入 |
| `model_ref` | 模型注册版本号，格式 `{seq}-{framework}@ds{version}`，如 `3-yolo@ds1`；镜像 tag 由其派生（`3-yolo-ds1`） |
| `model.yaml` | 随模型镜像发布的模型能力描述（skillname/类别/推荐阈值/张量契约 + 预留字段，B 原样保存） |
| 工位模板 | B 本地配置（工位 → 模型 + 类别子集 + 阈值 + 切片参数），GUI 编辑，A 不感知 |
| `station_code` | B 侧工位 code；A 只作不透明字符串存储 |
| `verdict` | 初检判定：`auto_pass` / `recheck` / `manual` |
| 错图 | **坏图**（采集/解码/推理失败）+ **可疑图**（`verdict != auto_pass`）；错图回传 = B→A |
| 信息统计 | 检测量、三档分布、缺陷 TopN、节拍、时延 P95、工位在线、模型/方案版本等运行统计 |
| 日报 | B 侧每日 00:10 自动生成的运行日报（HTML + CSV） |

## 5. 文档维护规则

1. 架构与边界变更 → 先改 `双平台架构与拆分方案.md`，再同步契约与计划。
2. 接口/表结构变更 → 改对应契约 + stub + fixture + 契约测试；跨平台接口变更需 A/B 双方确认。
3. 每份契约头部标注「归属」「冻结版本」「变更窗口」；计划文档每 D2/D9/D15 评审后更新。
4. 代码仓库根 `README.md` 已同步为双平台形态（含两平台目录、开发启动、页面入口）；骨架落地后按实际目录回填「已落地/规划中」标记。
