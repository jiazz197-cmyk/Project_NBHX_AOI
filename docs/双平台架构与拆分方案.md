# AOI 双平台架构与拆分方案

> 归属：全员（B 主笔架构、C 主笔公共包、A 主笔部署拓扑）；冻结：D2；变更窗口：D9 / D15。
> 依据：本文件是双平台边界的**唯一裁决来源**；接口细节见 `contracts/` 三份契约，排期见 `MVP开发计划.md`，骨架见 `P0骨架设计_双平台.md`。

---

## 0. 结论速览

| 项 | 结论 |
|---|---|
| 平台数量 | 2 个，跨机器部署，各自独立前端 + 独立后端，可独立发版、独立重启 |
| 平台 A | **训练与标注平台**（`aoi-train`）：LS 1.x 二开，中心侧，账户复用 LS、**RBAC 自研**；训练/标注/预标/复审/方案模板/模型注册 |
| 平台 B | **推理与检测平台**（`aoi-infer`）：产线侧，**无 RBAC**，独立前后端；接收模型→按模板推理→统计/日报/错图回传 |
| 公共部分 | **只有 `packages/skillname` 与 `packages/pipeline-core`** 两个纯 Python 包；无共享数据库、无共享中间件、无共享服务 |
| 跨平台链路 | ① 模型下发 A→B（HTTP 分片推送 + sha256 校验）② 方案下发 A→B ③ 错图回传 B→A ④ 心跳 B→A |
| 数据归属 | 主数据（字典/数据集/模型/方案/工位）在 A；运行数据（检测记录/图/统计/日报）在 B；可疑图与坏图回传后由 A 持有并进入复审回流 |
| 认证 | 平台间共享密钥（非用户身份）：A→B `X-Platform-Token`，B→A `X-Internal-Token`；B 前端无登录 |
| 轻量约束 | B 不引入 Redis / Celery / MinIO / Nginx（可选）；单 Python 进程 + SQLite + 本地磁盘 + 静态前端 |
| 网络 | 允许 A→B 单向发起为主；B 断网时继续推理，回传进本地 outbox，恢复后补传 |

## 1. 拆分动因

1. **部署位置不同**：训练/标注在中心机房（办公网、GPU 训练、数据资产）；推理/相机在产线现场（工控机/边缘服务器、靠近相机、7×24）。跨机器部署是既定事实，不应把产线运行绑在中心平台的可用性上。
2. **职责与变更频率不同**：A 侧围绕「数据资产 + 模型生产」，迭代慢、重权限、重审计；B 侧围绕「在线推理 + 运行监控」，迭代快、轻权限、重稳定与低时延。
3. **资源与依赖不同**：A 需要 PostgreSQL + MinIO + Redis + Celery + GPU 训练；B 只需要一个 Python 进程 + SQLite + 本地磁盘 + 推理 GPU/CPU。强行共用一套基础设施会让 B 变重、也让 A 的故障域扩散到产线。
4. **权限模型不同**：A 有标注员/工程师/管理员三角色与完整的**自研** RBAC（LS 原生角色框架不可用）；B 是现场运行看板与推理服务，**不需要用户体系**，用共享密钥做平台间认证即可。

## 2. 平台 A：训练与标注平台（`aoi-train`）

### 2.1 定位

数据资产与模型生产的**唯一主数据源**。基于 Label Studio 1.x 二开，深度复用其账户与登录/标注/上传/审核/导出能力；**角色与权限不复用 LS，由 aoi 自研 RBAC**（LS 原生角色/组织权限框架不可用）。

### 2.2 职责

| 模块 | 内容 |
|---|---|
| core | **自研 RBAC**：三角色（标注员/工程师/管理员）+ 权限点 + 授权表 + DRF 权限类；request_id、错误码 |
| datasets | 缺陷字典、label config 生成、导入包裹（去重/质检/元数据）、数据集版本与划分红线、LS data_export 包裹 |
| prelabel | 预标任务、**A 侧自实现 LS ML backend 协议**（`/api/prelabel/{task_id}/*`）、三桶路由统计 |
| training | 训练任务、门禁、ONNX 导出、模型注册与 lifecycle、审批、**模型下发（推送到 B）** |
| review | 检测事实接收（来自 B）、复审工作项、终裁、建议清单、坏图管理、回流 |
| plans | 检测方案模板 CRUD / 版本 / 激活（激活时推送到 B） |
| system | 工位主数据（`ST01`~`ST08`）、B 实例注册与心跳 |
| audit | 关键操作审计日志（`aoi_audit.audit_log`） |
| reports | 数据/训练侧统计（可选，最后做） |

### 2.3 技术栈与部署

- 后端：Django + DRF（LS 1.x fork），PostgreSQL 15，MinIO，Redis 7 + Celery 5（训练/导入/下发任务）。
- 前端：LS 1.x web（React + TS）二开页面。
- 推理：预标签用 ONNX Runtime + `pipeline-core`，在 A 侧 Celery GPU worker 内执行。
- 部署：中心侧单机 Docker Compose（nginx + ls-backend + workers + pg + minio + redis）。

### 2.4 与原方案的差异

- **取消 sidecar 服务**：原 sidecar 的 ML backend 协议与预标推理归 A 自身（Django + Celery worker + `pipeline-core`）；`/inspect/*`、相机、统计、日报归 B。
- 训练进度 SSE 由 A 提供（`GET /api/train/jobs/{id}/progress`），不再依赖 sidecar。
- 方案激活由 A 推送到 B（`POST {B}/api/v1/ingest/plan`），不再有 `POST /sidecar/plans/reload`。

## 3. 平台 B：推理与检测平台（`aoi-infer`）

### 3.1 定位

产线现场的**在线推理与运行监控平台**。自包含、无 RBAC、尽量轻量；只接受 A 下发的训练好的 YOLO 模型与方案模板，按模板推理并产出统计、日报与错图回传。

### 3.2 职责

| 模块 | 内容 |
|---|---|
| ingest | 接收 A 下发的模型（分片上传 + sha256 校验 + 落盘注册）与方案（校验 + 热加载 + 激活） |
| inference | ONNX Runtime 推理适配器、按 `pipeline-core` 切片/合并/三档判定、多模型按对象分发 |
| camera | 相机/通道适配器（DirectorySource 仿真、真实 GigE/RTSP）、软触发采集、坏图登记 |
| records | 检测记录与图片本地存储、保留策略、查询 |
| stats | 错图统计、信息统计、按工位/时段/缺陷类聚合 |
| report | 日报生成（每日 00:10）、HTML 展示、CSV 导出、保留 90 天 |
| outbox | 错图回传队列、失败重试、断点补传、状态可视化 |
| ops | 健康检查、磁盘/GPU/队列水位、日志轮转、模型版本管理、备份 |

### 3.3 技术栈（轻量基线）

| 层 | 选型 | 说明 |
|---|---|---|
| 后端 | FastAPI + Uvicorn（单进程） | 无 Django、无 RBAC、无多租户 |
| 数据库 | **SQLite（WAL）** | 可切 PostgreSQL（同一 ORM），MVP 默认 SQLite |
| 存储 | 本地磁盘 | 图片/缩略图/模型权重/日报，无 MinIO 依赖 |
| 定时任务 | APScheduler（进程内） | 日报、统计滚动、保留清理、心跳、outbox 重试 |
| 推理 | ONNX Runtime（CUDA EP 或 CPU） | FP32/FP16，`INSPECT_CONCURRENCY=2` |
| 计算内核 | `pipeline-core` + `skillname` | 与 A 共享的唯一代码层 |
| 前端 | Vite + React + TS + Ant Design 5 + ECharts | **独立前端**，不复用 LS web 组件；构建产物由 FastAPI 托管 |
| 部署 | Docker Compose 或 systemd + 静态目录 | 单机；无 Redis/Celery/MinIO/Nginx 依赖 |

### 3.4 无 RBAC 的安全边界（必须写进运维手册）

1. B **不做用户体系、不做登录、不做角色权限**；前端与查询接口默认只在内网/产线网段暴露。
2. 平台间接口用共享密钥：A→B 的 `/api/v1/ingest/*` 校验 `X-Platform-Token`；B→A 的回传带 `X-Internal-Token`。
3. 写操作（模型激活、方案切换、工位启停、保留策略）**建议**在部署时配置单一运维口令 `OPS_TOKEN`（环境变量，非用户体系）；未配置时仅允许内网访问。
4. B 不暴露数据库与文件目录；图片通过受控接口读取。
5. 跨机器链路建议走 HTTPS（内网 CA 或自签 + 指纹校验）或专线/VPN；不得裸露在公网。

### 3.5 轻量化硬约束（评审红线）

- 不引入 Redis、Celery、RabbitMQ、MinIO、Kafka、Nginx（可选）、K8s。
- 不引入 Django/DRF、不引入 LS 前端组件库。
- 数据库默认 SQLite；不得为 MVP 引入独立的 PostgreSQL 实例（需要时可切，但不是默认）。
- 进程数：1 个 Uvicorn 进程 + 进程内线程池；定时任务用 APScheduler，不另起 worker 服务。
- 前端首屏静态资源 ≤ 2MB（gzip 后），5 个页面；不做视频流与大屏。

## 5. 唯一公共层：`packages/`

> 原则：**公共部分只保留「跨平台语义」与「纯计算」**。凡是带框架、带业务表、带权限的代码一律不共享。

### 5.1 `packages/skillname`（词汇表，零三方依赖）

```python
# packages/skillname/skillname/__init__.py
class SkillName(str, Enum):                      # 兼容 Python 3.10（不用 enum.StrEnum）
    OBJECT_DETECTION = "ObjectDetection"        # MVP 唯一
    IMAGE_CLASSIFICATION = "ImageClassification" # 预留
    IMAGE_SEGMENTATION = "ImageSegmentation"     # 预留

# skillname → LS 控件映射（A 生成 label config 用；B 只做校验）
SKILL_TO_LS_CONTROL: dict[SkillName, str] = {
    SkillName.OBJECT_DETECTION: "RectangleLabels",
}

class ModelLifecycle(str, Enum):      # candidate / approved / online / retired
class DatasetSubset(str, Enum):       # train / val / test
class Verdict(str, Enum):             # auto_pass / recheck / manual（判定语义在 pipeline-core）

def is_valid_fault_code(code: str) -> bool          # ^object_fault_type_\d{2}$
def is_valid_plan_id(plan_id: str) -> bool          # ^[A-Z0-9-]{4,64}$
def format_model_ref(seq: int, framework: str, dataset_version: str) -> str
def parse_model_ref(ref: str) -> ModelRef           # {seq}-{framework}@ds{version}
```

- 为什么独立成包：LS 上游 `ml_models.SkillNames` 只有 `TextClassification` / `NamedEntityRecognition`，**没有目标检测**；AOI 需要自建任务类型枚举（`ObjectDetection` → `RectangleLabels`），且 A/B 两侧必须用同一套 code / model_ref / plan_id 规范。
- 依赖：仅 Python 标准库（`enum`/`re`/`dataclasses`），**不得引入 pydantic/django/fastapi**；`requires-python >=3.10`，枚举用 `(str, Enum)` 写法。

### 5.2 `packages/pipeline-core`（推理内核，框架无关）

```python
@dataclass(frozen=True)
class DetectBox:   xyxy: tuple[float, float, float, float]; class_id: int; object_code: str; score: float; model_ref: str = ""
@dataclass
class DetectResult: boxes: list[DetectBox]; tiling_meta: dict; verdict: str; verdict_reasons: list[str]
@dataclass
class ObjectSpec:   code: str; model_ref: str; class_map: dict[int, str]; recheck_min: float; auto_min: float; risk_level: int
@dataclass
class PipelineConfig: objects: list[ObjectSpec]; tile_size: int = 1280; overlap: float = 0.2
@dataclass
class StationSpec:  code: str; plan: str; enabled: bool
@dataclass
class PlanConfig:   plan_id: str; version: int; objects: list[ObjectSpec]; stations: dict[str, StationSpec]

class RuntimeModel(ABC):            # 推理后端由调用方注入
    def infer(self, tiles: list[np.ndarray]) -> list[list[RawBox]]: ...

def slice_image(img, tile_size=1280, overlap=0.2) -> list[Tile]
def box_to_global(box, offset) -> DetectBox
def merge_across_tiles(boxes, iou_thr=0.5) -> list[DetectBox]
def decide_verdict(boxes, cfg) -> tuple[str, list[str]]      # 宁错不漏，逐对象阈值
def run(image, cfg, models: Mapping[str, RuntimeModel]) -> DetectResult
def load_plan(yaml_text: str) -> PlanConfig                  # 方案模板结构校验
class StubRuntimeModel(RuntimeModel)                         # 确定性假框，供 P0/测试
```

- 依赖：`numpy` + `pillow`；`pyyaml` 为 `load_plan` 的可选 extra（`pipeline-core[yaml]`）。**不依赖 onnxruntime**——A 与 B 各自提供 `OnnxRuntimeModel` 适配器。
- 两侧复用点：A 的预标推理（ML backend）、B 的在线推理，共用同一套切片/合并/判定逻辑，保证「预标结果」与「产线判定」语义一致。
- 版本策略：语义化版本（MVP `0.1.0` 起）；A/B 在交付时锁同一版本；破坏性变更需双端契约测试通过（`tests/contracts/`）。

### 5.3 为什么不再共享更多

| 候选 | 不共享的原因 |
|---|---|
| ORM 模型 / 表结构 | A 用 Django ORM + PostgreSQL；B 用 SQLAlchemy + SQLite。强行共享会把 Django 依赖带进 B |
| 请求/响应 Pydantic 模型 | A 用 DRF Serializer；B 用 Pydantic。共享需引入双方框架依赖，收益低 |
| 统一信封 / 错误码实现 | 语义共享（契约层），实现各写一份（各 30 行），避免跨平台版本耦合 |
| 方案模板存储/版本管理 | 主数据在 A（表 + 审批 + 激活）；B 只消费，不反向写 |
| 事件总线 | B 轻量自包含，不接 Redis Streams；跨平台交互全部走显式 HTTP 契约 |
| RBAC / 权限模型 | A 自研（`aoi_core`），B 无用户体系；共享会把 A 的授权模型带进 B |

## 6. 部署拓扑与跨机通信

### 6.1 拓扑

```
中心侧（办公网/机房）                          产线侧（工控机/边缘服务器，可多台）
┌──────────────────────────────┐             ┌──────────────────────────────┐
│ 平台 A                        │  A→B 推送   │ 平台 B                        │
│  nginx:443/8080               │ ──────────▶ │  uvicorn:8990（API + 静态前端）│
│  ls-backend:8000 (Django)     │             │  sqlite: infer.db             │
│  worker-gpu / worker-cpu      │  B→A 回传   │  /data/images /data/models    │
│  PostgreSQL / MinIO / Redis   │ ◀────────── │  /data/reports                │
└──────────────────────────────┘             └──────────────────────────────┘
                                                  │ GigE / RTSP / 目录仿真
                                                  ▼
                                              相机 / 工位 ST01~ST08
```

- A 与 B **不在同一台机器**，不共享数据库、不共享对象存储、不共享 Redis。
- B 可部署多实例（每条产线一个），MVP 支持 1 个实例，模型/方案下发按 `target_code` 预留多实例字段。
- 时间同步：两侧必须启用 NTP；B 上报时钟偏差，偏差 > 2s 告警（影响日报与回传时间口径）。

### 6.2 端口与环境变量

| 侧 | 变量 | 说明 |
|---|---|---|
| A | `INFER_PLATFORM_BASE_URL` | B 的基址，如 `https://10.0.10.9:8990` |
| A | `INFER_PLATFORM_TOKEN` | A→B 的 `X-Platform-Token` |
| A | `INTERNAL_TOKEN` | B→A 回传/心跳校验（同现有内部头） |
| B | `PLATFORM_TOKEN` | 校验 A→B 请求（= A 的 `INFER_PLATFORM_TOKEN`） |
| B | `TRAIN_PLATFORM_BASE_URL` | A 的基址，如 `https://aoi-train.corp:8080` |
| B | `INTERNAL_TOKEN` | B→A 回传/心跳携带 |
| B | `OPS_TOKEN` | 可选，B 前端写操作口令（非 RBAC） |

### 6.3 网络与断连策略

| 场景 | 行为 |
|---|---|
| A→B 下发失败 | A 侧 `model_dispatch` 记 `failed`，指数退避重试 3 次，可人工重推；B 侧保留未完成分片 24h 供断点续传 |
| B→A 回传失败 | 进入本地 outbox，退避重试（1m/5m/15m/1h，最长 24h）；未回传成功的图片**不参与保留清理** |
| A 长时间不可用 | B 用已激活方案继续推理与统计，日报照常生成；回传积压，UI 显示 pending 数量 |
| B 长时间不可用 | A 侧心跳超时告警（>5min），模型/方案下发排队，不影响 A 的训练与标注 |
| 跨机时钟漂移 | 双时间戳：`captured_at`（采集，B 本地时钟）+ `received_at`（A 接收时钟）；日报以 `captured_at` 为准 |

## 7. 数据归属与流动

| 数据 | 归属 | 流动 |
|---|---|---|
| 缺陷字典 / 数据集 / 标注 / 训练任务 / 模型注册表 | A | 不流向 B（B 只接收模型二进制与元数据副本） |
| 方案模板 / 工位主数据 | A | A→B 推送（B 只读缓存） |
| 模型权重（ONNX） | A 产出 | A→B 推送，B 本地落盘并校验 sha256 |
| 检测记录（全量）/ 图片 / 统计 / 日报 | B | 留在 B；仅可疑图与坏图回传 A |
| 可疑图（`verdict != auto_pass`） | A（回传后） | B→A，A 落 `image` + `inspection_fact` + `review_workitem` |
| 坏图（采集/解码/推理失败） | A（回传后） | B→A，A 落 `bad_image` |
| 复审终裁 / 建议 / 回流数据 | A | 人工确认后以 `source=reflux_review` 进数据集候选（红线：不进测试集） |

> 幂等主键：跨平台回传以 `(station_code, seq)` 去重（`suspicious` 落 `inspection_fact`、`bad` 落 `bad_image`）；A 侧重复请求返回既有 id 并标记 `duplicated=true`。

## 8. 关键链路时序

### 8.1 模型下发（A→B）

```
B: GET /api/v1/health 可达
A: 训练完成 → 门禁通过 → 人工审批(lifecycle=approved)
A: POST {B}/api/v1/ingest/model            # 元数据 + sha256 + size
B: 返回 {upload_id, exists}                 # 幂等：同 ref+sha256 直接 exists=true
A: PUT  {B}/api/v1/ingest/model/{upload_id}/blob   # 分片 1~4MB，Content-Range，可断点续传
A: POST {B}/api/v1/ingest/model/{upload_id}/commit # B 校验 sha256 → 落盘 → 注册 ready
B: → {status: ready, model_ref}
A: 记 model_dispatch=ready
```

### 8.2 方案激活（A→B）

```
A: 方案校验（schema/字典/模型注册表/工位） → 写 aoi_plans.plan_version
A: POST {B}/api/v1/ingest/plan {plan_id, version, checksum, content_yaml, stations, dictionary}
B: pipeline-core.load_plan 校验 → 检查 model_ref 均已 ready → 字典快照落库
B: 加载 ONNX 会话 → 加载自检（张量匹配 + 空跑）→ 原子切换 active plan
B: → {ok, loaded_models, checks[]}
A: 全部成功才标 active；失败保持旧版本 active 并返回 42200/50300
```

### 8.3 推理与错图回传（B→A）

```
相机/模拟器 → POST {B}/api/v1/inspect/image (multipart)
B: 解码 → pipeline-core.run(切片→推理→合并→三档判定) → 落 inspection
B: verdict != auto_pass 或坏图 → 写 outbox → 异步 POST {A}/api/ingest/findings
A: 图片落 MinIO → image 行 → inspection_fact → review_workitem / bad_image
A: → {fact_id, workitem_id, image_id, bad_image_id, duplicated}
B: outbox 标记 pushed
```

### 8.4 日报

```
APScheduler 00:10 → 聚合昨日 inspection/stats_daily → Jinja2 渲染 HTML → 落 /data/reports/{day}.html + CSV
前端「日报」页 → 列表 / 详情 / 导出
```

## 9. 与旧方案（LS 二开 + sidecar）的差异对照

| 维度 | 旧方案 | 新方案 |
|---|---|---|
| 服务数 | LS 主应用 + sidecar | 平台 A + 平台 B（各自独立前后端） |
| sidecar | FastAPI 侧车，与 A 同机，共用 MinIO/JWT | **取消**；预标归 A，在线推理归 B |
| 认证 | sidecar 验 LS JWT；内部头 | 平台间共享密钥；B 无用户体系 |
| 共享代码 | `packages/pipeline-core` + events/trainers/exporters/common | 只保留 `skillname` + `pipeline-core` |
| 数据库 | 全部在 A 的 PG，sidecar 不直连 | A 用 PG；B 用独立 SQLite，不跨机直连 |
| 模型交付 | B 读 A 的 MinIO `models/` | A→B HTTP 分片推送 + sha256（跨机器，不依赖共享存储） |
| 方案激活 | A 调 `/sidecar/plans/reload` | A 推 `POST {B}/api/v1/ingest/plan` |
| 检测事实 | sidecar 写 A 的 `/api/review/facts` | B 回传 `/api/ingest/findings`（仅可疑/坏图） |
| 统计/日报 | A 侧报告（最后做、可砍） | **B 侧核心能力**（错图统计/信息统计/日报） |
| 前端 | 全部在 LS web 内 | A 用 LS web；B 用独立 Vite React 前端 |
| 断网可用性 | sidecar 与 A 同机，无独立断网能力 | B 断网可继续推理，回传积压补传 |

## 10. 二期演进（本期只冻结接口，不实现）

1. **B 多实例**：按 `target_code` 管理多条产线；A 侧批量下发、按实例查看心跳与统计。
