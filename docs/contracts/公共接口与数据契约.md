# AOI MVP 公共接口与数据契约（工程级）

> 冻结基线：D2；维护：B（主数据源/业务接口/二开包裹）、C（sidecar/pipeline-core）、A（部署/路由/存储）。
> 变更规则：新增字段随时可提、破坏性变更需三方一致；每次变更同步本文档、stub 与契约测试。

### 0.1 技术栈基线（与 MVP 手册一致，冲突时以本基线复核 MVP）

| 层 | 选型 |
|---|---|
| 数据库 | PostgreSQL 15；本地开发与交付均不用 SQLite |
| 对象存储 | MinIO（bucket：`aoi-images` 等）；数据集图片/上传文件默认走 MinIO |
| 异步任务 | **Celery 5**；明确不使用 RQ / django_rq |
| Broker / 事件 / 缓存 | Redis 7（Celery broker + Redis Streams + pub/sub） |
| 主后端 | Django + DRF（LS 1.x） |
| 主前端 | LS 1.x web（React + TS） |
| 推理计算 | FastAPI + Uvicorn（sidecar） |
| 交付 | Docker Compose + 离线镜像包 |

> Redis/Celery 是跨模块公共中间件。MVP 前期不要求立即在代码中启用，先冻结本契约并明确 A/B/C 分工；实现时统一 Celery，不引入 RQ。

**待确认假设（若与你的想法不符，开发前纠正）：**
- 假设 1：「错误图片回传」= ① 采集/解码失败坏图 → C 登记 `POST /api/review/bad-images`，转人工重标签/重传；② 推理可疑图（verdict=recheck/manual）→ 直接进人工复审工作项，终裁后按规则回流重标注。
- 假设 2：MVP 中训练与推理**人工互斥**（compose profiles 二选一启动），系统不做自动退载/恢复（二期做分时调度）。
- 假设 3：LS 版本行为以「复用验证日」（D2）实测为准；本文档中标注「以 LS 1.23.0 实测为准」的条目，若实测不符，当天定降级方案并回写本文档。

## 0.5 LS 原生复用对照表（MVP 第一原则：能用 LS 的绝不自己写）

| 平台功能 | LS 原生能力（直接复用） | aoi 二开薄包裹 | MVP 决策 |
|---|---|---|---|
| 登录/令牌 | LS token API（JWT HS256，claims 含 `user_id`） | 无；sidecar 同 SECRET 验签 | **复用** |
| 用户/组织/角色 | LS users + 组织角色框架 | 三角色↔LS 角色映射 + 权限点表（aoi/core） | 复用+映射 |
| 标注项目/任务 | `projects/tasks/annotations` 原生 | label config 由缺陷字典渲染注入 | **复用** |
| 框标注交互 | 标注编辑器（RectangleLabels） | 零改动（红线） | **复用** |
| 数据浏览 | Data Manager | 零重构（红线） | **复用** |
| 标注审核 | LS Review 流（标注→审核） | aoi 只读投影统计；不满足再降级平台审核接口 | **复用** |
| 文件上传/存储 | LS 文件存储（仓库默认已接 MinIO，业务数据在 PostgreSQL）+ 预签名 URL + 缩略图 | aoi 导入包裹：去重/质检/元数据登记 | 复用+包裹 |
| 预标回写 | `ml/` MLBackend 连接器 + Batch predictions + 交互预标 | aoi 任务表 + 三桶路由统计 | **复用** |
| 数据集导出 | `data_export`（YOLO/COCO） | aoi 版本绑定 + 测试集红线 + data.yaml 校验 | **复用** |
| 前端框架 | web/apps 组件库/路由/auth store/i18n | Menubar 入口 + 4 个新页面 | 复用+加页 |
| 审计（部分） | LS activity log | aoi/audit 关键操作追加写 | 复用+补充 |

**结论**：MVP 中「账户、标注、上传、预标通道、导出、审核」六块几乎零开发，B 的主战场是「字典/数据集版本/训练/复审/方案模板」五个新域 + 薄包裹。

## 1. 通用工程约定

### 1.1 术语与枚举（全文统一）

| 术语 | 定义 |
|---|---|
| `object_fault_type_XX` | 缺陷对象 code，XX 两位数字（01~99），由缺陷字典配置，可扩展数十类 |
| `model_ref` | 模型注册版本号，格式 `{seq}-{framework}@ds{version}`，如 `3-yolo@ds1` |
| `plan_id` / `plan_version` | 检测方案模板标识与版本（正整数递增） |
| `station_id` | 工位；工位 code `ST01`~`ST08` |
| `verdict` | 初检判定：`auto_pass` / `recheck` / `manual` |
| `fact` / `workitem` | 检测事实（inspection_fact）/ 复审工作项 |
| `source` | 图片来源：`manual_real`（人工标注真实图）/ `camera`（相机采集）/ `reflux_review`（复审回流）/ `prelabel_model_{id}`（预标） |

### 1.2 网络与路由（A 维护 nginx，D2 定稿）

| 路径 | 上游 | 说明 |
|---|---|---|
| `/` | web（LS 前端静态 + 二开页面） | SPA 路由回退 `/index.html` |
| `/api/*` | ls-backend:8080 | **LS 原生 + aoi 二开全部接口**（同一个 DRF 根） |
| `/sidecar/*` | sidecar:8990（转发去掉前缀） | C 的推理服务 |
| `/data/*`、`/upload/*` | ls-backend:8080 | LS 媒体/上传文件（预签名下载） |
| `/healthz` | 各服务独立 | A 的 compose healthcheck |

### 1.3 统一响应信封与错误码

成功：`{"code": 0, "message": "ok", "request_id": "req-...", "data": {...}}`
失败：HTTP 状态码 + 同信封（`data.detail.fields` 给字段级错误）：

| HTTP | code | 含义 | 产生方 |
|---|---|---|---|
| 400 | 40010 | 坏图/文件不可读 | C、B |
| 401 | 40100 | 未认证/令牌过期 | B、C |
| 403 | 40300 | 无权限（角色/权限点不满足） | B、C |
| 404 | 40401 / 40402 | 资源不存在 / 工位未注册未启用 | B / C |
| 409 | 40900 | 状态冲突（重复激活/重复批次） | B、C |
| 422 | 42200 | 业务校验失败（`detail.fields`） | B、C |
| 429 | 42900 | 工位忙/队列背压（可重试） | C |
| 500 | 50000 | 内部错误 | B、C |
| 503 | 50300 | 服务不可用（推理未就绪/方案未激活） | C |

### 1.4 鉴权契约（**LS 原生 JWT，零侵入**）

- **前端 → Django**：LS 原生 token API 签发的 JWT（HS256，`JWT_SECRET` = LS 的 `SECRET_KEY` 同源设置，claims 含 `user_id`）。二开权限点存 aoi 表，由 Django 侧 DRF 权限类判断（不动 LS 登录链）。
- **前端 → sidecar**：sidecar 用同一 SECRET 验签 LS JWT，取 `user_id`；需要角色判断时调 `GET /api/core/permissions`（X-Internal-Token，缓存 5 分钟）。**骨架阶段**：验签通过 + user_id 存在即放行；角色细化在 D4 RBAC 落地时接上。
- **Django → sidecar（内部）**：`X-Internal-Token: <INTERNAL_TOKEN>`，跳过角色校验；`X-User-Id` 供审计。
- **C → Django（写 facts 等）**：同上内部头。
- **开发令牌**：`sidecar/dev_token.py` 签发与 LS 同构的测试 JWT（供 A 模拟器/前端联调）。
- 权限点（MVP 模块级）：`datasets.*`、`training.*`、`review.*`、`plans.*`、`system.*`，动作 `view/create/update/cancel/approve/rollback`。

### 1.5 公共请求约定

- 请求头：`X-Request-ID`（nginx 生成并贯穿所有服务日志）；`Idempotency-Key`（导入/训练/激活等写操作必带）。
- 时间 ISO8601 UTC；编码 UTF-8；分页 `?page=&page_size=`，响应 `{total, items}`。
- 文件上传 multipart：字段 `file`/`files`，单图 ≤100MB；MVP 不做分片断点。

## 3. REST API 规格（Django `/api/*`，B 维护）

> 前缀说明：`/api/*` 下同时挂 **LS 原生端点**（登录/项目/任务/标注/上传/导出等，零改动）与 **aoi 二开端点**（下文清单）。二开端点统一信封（§1.3）；LS 原生端点维持 LS 原格式（前端页面直接复用）。

### 3.0 二开端点通用

- 鉴权：LS JWT（§1.4）+ DRF 权限类（模块级权限点）。
- `GET /api/core/permissions`（内部头）：返回 `{user_id, role, perms:[...]}`，供 sidecar 权限查证（缓存 5min）。

### 3.1 数据域 `/api/datasets`（导入/导出复用 LS，aoi 薄包裹）

| 方法/路径 | 权限 | 说明 |
|---|---|---|
| `POST /import` | datasets.create | **包裹 LS 上传**：内部走 LS Upload API/预签名入 LS 默认存储（MinIO）→ aoi 去重(md5)/坏图质检/元数据登记 → 登记入 LS project 任务。multipart `files[]` + form `source`/`station_id`，`Idempotency-Key` → `{job_id}` |
| `GET /import/{job_id}` | datasets.view | `{status, total, ok, dup, bad, bad_items:[{filename, reason}]}` |
| `GET /images`、`GET /images/{id}/download` | datasets.view | 筛选/预签名下载（复用 LS 存储） |
| `GET/POST/PUT /defects`、`POST /defects/publish` | datasets.* | 字典 CRUD；发布 → 渲染 label config（RectangleLabels，code=object_fault_type_XX）+ 版本快照 |
| `CRUD /datasets`、`POST /datasets/{id}/versions` | datasets.* | 数据集/版本；发布触发划分+**测试集红线**（违反→42200） |
| `GET /datasets/{id}/versions/{v}/export` | datasets.view | **复用 LS data_export（YOLO）**：绑定版本的标注导出 → zip 落 MinIO `datasets/exports/`（§10） |
| `GET /annotation-stats` | datasets.view | LS 标注/审核状态的只读投影（复用 LS 原生，不建表） |

导入请求示例：
```http
POST /api/datasets/import
Authorization: Bearer <LS-JWT>
Idempotency-Key: imp-20260908-001
Content-Type: multipart/form-data
-- source=manual_real, station_id=2, files[]=@d1.jpg, files[]=@d2.jpg
→ {"code":0,"data":{"job_id": 41, "queued": 2}}
```

### 3.2 训练域 `/api/train`

| 方法/路径 | 权限 | 说明 |
|---|---|---|
| `GET /presets` | training.view | 预置方案列表 + 可编辑字段 Schema |

| `GET /jobs/{id}` / `POST /jobs/{id}/cancel` | training.view/cancel | 状态/指标/取消 |

### 3.3 复审域 `/api/review`

| 方法/路径 | 权限 | 说明 |
|---|---|---|

### 3.4 方案模板域 `/api/inspect/plans`（B 拥有；C 消费激活）

| 方法/路径 | 权限 | 说明 |
|---|---|---|
| `GET/POST /plans` | plans.view/create | `{plan_id, name, content_yaml}` → 自动 version=1 |
| `GET /plans/{plan_id}/versions`、`.../versions/{v}` | plans.view | 版本列表 / yaml+checksum |
| `POST /plans/{plan_id}/versions/{v}/activate` | plans.update | **同步整链**：B 校验 → 写 MinIO `plans/` → 调 `POST /sidecar/plans/reload` → C 校验+热加载+金标准自检 → 回写 → 标 `active`。失败 42200/50300 不落 active |

激活时序：
```
前端 --activate--> B(校验 schema/字典/模型注册表) --写桶--> MinIO plans/
B --POST /sidecar/plans/reload {plan_id,version}--> C
C: 校验 code/model_ref/阈值 → 加载模型 → 金标准自检
C --{ok,loaded_models,checks}--> B --plan_version.active + plan.activated 事件--> 全员
```

### 3.5 系统域 `/api/system`

|---|---|---|
| `CRUD /stations` | system.* | `{code, name, enabled, channel_id, config, plan_id, plan_version}` |

| `GET /audit` | system.view（仅管理员） | 审计查询（LS activity log 之外的 aoi 关键操作） |

## 4. sidecar 接口规格（`/sidecar/*`）

> **归属**：sidecar 由 C 维护运行；路由聚合/鉴权中间件（§1.4 LS JWT 验签）、`/progress` SSE、ML backend 协议骨架为 B、C 共担（B 契约+C 实现）；`/inspect/*`、`/models/*`、`/plans/reload` 与 pipeline-core 归 C。

### 4.1 健康与模型

```json
GET /sidecar/health
{"code":0,"data":{"status":"UP","gpu":{"device":0,"mem_used_gb":3.2,"mem_total_gb":23.7},
```

## 7. 检测方案模板 Schema（B 拥有；C 适配执行）

```yaml
# plans/PLAN-DOORPANEL-STD/v3.yaml
plan_id: PLAN-DOORPANEL-STD
version: 3
objects:
  - code: object_fault_type_01
    model_ref: 3-yolo@ds1
    class_map: {0: object_fault_type_01}
    thresholds: {recheck_min: 0.60, auto_min: 0.90}
    risk_level: 3
  - code: object_fault_type_02
    model_ref: 3-yolo@ds1
    class_map: {1: object_fault_type_02}
    thresholds: {recheck_min: 0.55, auto_min: 0.88}
    risk_level: 2
stations:
  ST01: {plan: PLAN-DOORPANEL-STD, enabled: true}
  ST02: {plan: PLAN-DOORPANEL-STD, enabled: true}
```

校验（B 保存、C reload 均执行，规则一致）：
1. `plan_id` 匹配 `^[A-Z0-9-]{4,64}$`；`objects` 非空、code 唯一。
2. `code` ∈ 缺陷字典 active 项。
3. `model_ref` ∈ 注册表且 `gate_status=passed`；`cover_classes` 含该 code；`task_type=ObjectDetection`（检测对象只能绑检测模型）。
4. `class_map` 非空、value 全等于该 code。
5. `0 < recheck_min < auto_min < 1`。
6. `stations` 的 code 存在于工位表；`enabled=true` 必须有绑定。
变更 = 新版本 + checksum；激活 = 标 active（旧版归档）；回滚 = 激活历史版本。

## 8. 推理数据契约（pipeline-core，C 拥有）

### 8.1 签名

```python
@dataclass
class DetectBox:   xyxy; class_id; object_code: str; score: float; model_ref: str = ""
@dataclass
class DetectResult: boxes; tiling_meta: dict; verdict: str; verdict_reasons: list[str]
@dataclass
class ObjectSpec:  code; model_ref; class_map: dict[int,str]; recheck_min; auto_min; risk_level
@dataclass
class PipelineConfig: objects: list[ObjectSpec]; tile_size=1280; overlap=0.2
class RuntimeModel(ABC): infer(tile) -> list[RawBox]
class StubRuntimeModel(RuntimeModel)          # P0/测试用：确定性假框（骨架文档 §3.3）

def slice_image(img, tile_size=1280, overlap=0.2) -> list[Tile]
def box_to_global(box, offset) -> DetectBox
def merge_across_tiles(boxes, iou_thr=0.5) -> list[DetectBox]
def decide_verdict(boxes, cfg) -> tuple[str, list[str]]   # 宁错不漏，逐对象阈值
def run(image, cfg, models: dict[str, RuntimeModel]) -> DetectResult
def load_plan(yaml_text) -> PlanConfig                     # §7 规则 1/4/5/6 结构校验
```

### 8.2 判定语义与 result_json（宁错不漏）

- `auto_pass`：无框或全框 `score≥auto_min` 且风险低/中；`recheck`：存在 `recheck_min≤score<auto_min` 或高风险框；`manual`：存在 `score<recheck_min` 或模型异常。不确定一律不自动放行。
- result_json（C → `POST /api/review/facts`）：
```json
{"boxes":[{"object_code":"object_fault_type_01","score":0.72,"model_ref":"3-yolo@ds1","xyxy":[100,200,180,260]}],
 "verdict":"recheck","verdict_reasons":["mid_score"],
 "tiling_meta":{"tile_size":1280,"overlap":0.2,"tiles":12,"ms":1400}}
```
- 多模型调度（MVP ≤2 检测模型）：按 `model_ref` 分组分发，模型内切片 batch，逐框带 `model_ref`。
