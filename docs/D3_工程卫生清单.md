## 7. D3 认证链路标准化（本次已处理，2026-09-10）

> 背景与改动清单见 `CHANGES.md` §认证链路标准化；契约面见 `docs/contracts/平台A_接口与数据契约.md` §2.4/§4.0。

| 原问题（D3 新登记） | 处置 |
|---|---|
| Bearer 由 Django 中间件赋值 `request.user`，不经 DRF 认证链（`request.auth` 为空、401 语义不一致、OpenAPI 不认） | 中间件从 `MIDDLEWARE` 移除；改为 `REST_FRAMEWORK.DEFAULT_AUTHENTICATION_CLASSES` 中的 `aoi.common.authentication.AoiJWTAuthentication`（延迟导入薄代理，理由：settings 导入期 `rest_framework.schemas` 会 eager import 认证类，simplejwt 在模块级 import `django.contrib.auth.models` → `AppRegistryNotReady`） |
| 无「账号密码换 token」端点（`/api/token/` 要求先有 session） | 新增 `POST /api/auth/login`（匿名，凭据校验与浏览器登录同源）、`POST /api/auth/logout`（黑名单，幂等） |
| 鉴权路径依赖 LaunchDarkly 旗标与组织级开关，失败只 log 不抛 | 随中间件一并移除；组织级 `JWTSettings.api_tokens_enabled` 仅保留在上游端点语义中 |
| `SIMPLE_JWT` 未配置（access 5 min / 签名密钥全靠默认） | 显式配置：HS256、access 30 min、refresh 7 天、`UPDATE_LAST_LOGIN=True`；**不开启 refresh 轮换**（PAT 是 200 年 refresh，轮换会让用户手上那份立即失效） |
| OpenAPI 缺 Bearer 安全方案（H25 的安全方案部分） | 新增 `aoi/common/schema.py::AoiBearerAuthScheme` + `AUTHENTICATION_WHITELIST`；schema 中 `/api/core/permissions` 现在同时给出 `Bearer` 与 `Token` |

**H25 更新**：本次新增的两个 auth 端点已带完整 `request`/`responses` schema（`@extend_schema` + 显式 serializer）；
其余 aoi 端点仍只有路径（沿用 `EmptySerializer` 占位），H25 的"每端点 request/response"部分**继续留在 D3~D4 待办**。
